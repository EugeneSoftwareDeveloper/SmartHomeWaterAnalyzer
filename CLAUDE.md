# SmartHomeWaterAnalyzer

Flutter-приложение для BLE-тестера качества воды YINMIK BLE-C600. Android, Riverpod, go_router, drift.

Подробный профиль проекта — в [`AGENTS.md`](./AGENTS.md), архитектура — в [`docs/01-architecture.md`](./docs/01-architecture.md). Перед широкими изменениями читай их.

## Команды

```powershell
flutter analyze                              # должно быть 0 issues
flutter test                                 # все тесты обязаны проходить
dart run build_runner build --delete-conflicting-outputs   # после правки схемы drift
flutter build apk --release --split-per-abi  # --split-per-abi обязателен, см. ниже
```

## Инварианты

Это решения, которые выглядят как недоделки и которые чинят «по-хорошему», ломая настоящее поведение. Не меняй их, не поняв причину.

**Замеры не сохраняются автоматически.** В историю попадает только то, что пользователь подтвердил кнопкой «Сохранить». Автосохранение при каждом чтении было убрано намеренно: калибровочные и тестовые замеры засоряли графики.

**`Measurements.label` хранит имя места строкой, а не ссылку на `Places`.** Это не забытая нормализация. Замер должен помнить, как место называлось в момент измерения; внешний ключ переписывал бы историю при переименовании или удалении места.

**Профиль норм хранится в замере (`Measurements.normsProfile`).** «Опасно / норма» — свойство замера, а не текущей настройки. Разбор только через `NormsProfile.resolve(..., fallback:)`: `null` (записи до 1.2.0) и незнакомое имя (запись из более новой версии) обязаны давать fallback, а не исключение.

**Геометка никогда не блокирует и не роняет сохранение.** `LocationService` возвращает `LocationResult` с причиной отказа вместо исключения и имеет жёсткий общий бюджет времени. Нет разрешения, выключен GPS, не пришёл фикс — замер всё равно сохраняется, просто без координат.

**Сравнение с прошлым замером считается по месту и прибору и не пересчитывается после сохранения.** База — последний замер того же прибора в том же месте (`HistoryRepository.latestForPlace`); сравнивать кран с бассейном значит рисовать скачок качества там, где сменили точку забора. После записи замера база намеренно **не** переезжает на него, иначе дельта, только что показанная пользователю, схлопывается в ноль.

**`WaterParameter.noiseThreshold` — не косметика.** Сдвиг меньше порога не считается изменением, даже если формально пересёк границу зон: pH 7.19 → 7.21 иначе объявлялся бы улучшением, хотя это паспортный разброс электрода. Новый параметр обязан задать порог не меньше единицы вывода (`10^-fractionDigits`) — это проверяется тестом.

**Имя места нормализуется одной функцией `normalizePlaceName` из `history/place_name.dart`.** Ею пользуются поле выбора, запись в БД и поиск базы для сравнения. Заведёшь вторую — сравнение начнёт искать «` Кулер `» там, где сохранено «`Кулер`», и молча ничего не найдёт.

**Версия Flutter в CI запинена** (`flutter-version` во всех job'ах `ci.yml` и `release.yml`). На плавающем `channel: stable` сборка уже ломалась: раннер уехал на новый Dart, а транзитивный `analyzer` из `pubspec.lock` не знал его синтаксиса. Поднимать версию — осознанно, вместе с `flutter pub upgrade`, одинаково в обоих файлах.

**`flutter build apk` требует `--split-per-abi`.** В `android/app/build.gradle.kts` включён ABI split с `isUniversalApk = false`, поэтому без флага fat-APK просто не создаётся, а сборка падает на его отсутствии.

**BLE-фильтр по имени работает через `contains`, а не `startsWith`,** и проверяет `advertisementData.advName` вдобавок к `platformName`. Платформенный фильтр `withServices: [serviceUuid]` с BLE-C600 **не работает** — прибор не объявляет сервис FF01 в advertisement.

## Обязательные шаги при изменениях

**Меняешь схему БД** → подними `schemaVersion`, добавь ветку в `onUpgrade`, перегенерируй drift **и напиши тест миграции на настоящем файле БД** по образцу `test/places_migration_test.dart`. In-memory база для этого не годится: она пересоздаётся на каждое соединение, и реальный путь обновления пользователя остаётся непроверенным.

**Меняешь состав модулей `lib/` или зависимости между ними** → обнови Mermaid-схему в `docs/01-architecture.md` тем же коммитом. Она объявлена частью контракта проекта; разошедшаяся с кодом схема вреднее отсутствующей, потому что по ней принимают решения.

**Пишешь чистую логику, которую хочется протестировать** → выноси top-level функцией в `lib/`, а не private-методом внутри виджета. Так сделаны `groupMeasurementsByDay`, `niceAxisInterval`, `buildMeasurementsCsv`.
